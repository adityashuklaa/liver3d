01

What happens to a scan

Seven stages. Each one records what it changed, so the mask can be pushed back onto the exact voxel grid the scan arrived on.

01IngestNIfTI file or DICOM series; pixel data plus spatial metadata.→ validated volume
02ValidateShape, affine, label values, spacing range, finite voxels.→ pass / warn / reject
03PreprocessOrient RAS, resample to 3 mm, clip −200…250 HU, scale 0–1.→ tensor + inverse record
043D U-NetSliding 48³ windows, Gaussian-blended at 50% overlap.→ probability map
05PostprocessThreshold 0.5, largest plausible component, fill holes.→ binary mask
06RestoreInvert resampling and orientation back to source geometry.→ aligned NIfTI
07ReviewOverlay, 3D surface, accept / correct / reject, audit event.→ signed-off artifact

06

What this run does and does not prove

Read this before quoting a number

These scores come from synthetic CT phantoms generated by the repository, not from patient data. They prove the pipeline is wired correctly end to end — preprocessing inverts, sampling works, inference blends, geometry survives the round trip, the service enforces its roles.

They say nothing about clinical accuracy. The source project reported Dice above 0.90 on real data, but no dataset, split, checkpoint or metric export was supplied with it, so that figure remains unverified here. Point the config at LiTS or CHAOS, lock a patient-level split, and the same three commands produce numbers that can be defended.

Standing limits, whatever the dataset:

  • Liver against background only — tumour segmentation is a separate task with separate labels and metrics.
  • A high Dice can still hide a boundary error that matters clinically; the worst cases get reviewed, not just the mean.
  • Performance on a public dataset does not transfer to a new scanner, protocol or population without external validation.
  • Research prototype. Not a cleared medical device, and not for patient care without institutional, clinical and regulatory approval.
07

Reproduce it in three commands

No dataset needed for the first one — it generates its own phantoms.

# everything on this page, from scratch, on CPU
python scripts/quickstart.py

# real data: lock a patient-level split, then train and evaluate once
python scripts/build_manifest.py --root data/lits --out data_manifests/split_v1.csv
python -m src.train    --config configs/baseline.yaml
python -m src.evaluate --checkpoint outputs/<run_id>/best.pt --split test

# serve it
set LIVER3D_CHECKPOINT=outputs/<run_id>/best.pt
set LIVER3D_API_KEYS=some-long-random-key:clinician
uvicorn src.api.service:app --port 8000
